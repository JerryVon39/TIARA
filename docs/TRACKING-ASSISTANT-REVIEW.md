本季列表展示 Bangumi 的首播日期。现有「联网查时刻」只在详情里按需查询，找到后也要手动采纳，本季和同步流程未使用这份数据。Bangumi 公开日历提供首播日和放送星期，分钟级时间需要独立数据。用当前缓存中的 81 部 TV 条目和本次下载的公开数据按 Bangumi ID 对照，71 部能通过现有解析器获得分钟级周播时刻。这个样本衡量的是首发或原播周档，平台更新时刻另有站点和地区字段。一次应用直连测试超时，随后通过命令行下载同一公开数据成功，缓存回退仍有必要。 [Bangumi 日历字段](https://github.com/bangumi/api/blob/master/open-api/api.yml) · [bangumi-data 放送周期与地区](https://github.com/bangumi-data/bangumi-data/blob/master/CONTRIBUTING.md#关于broadcast字段)

## 下一轮实施顺序

1. **账号连接与同步。** 将 Bangumi 设置和桌宠称呼拆开。增加「测试连接」，显示实际连接的账号、收藏权限和代理状态，区分令牌失效、账号不符、代理故障、限流与超时。提供替换、清除令牌的入口。账号响应和诊断日志只显示脱敏配置。
2. **同步预览与确认。** 区分公开日历、在看收藏和观看进度，默认保留本地进度，导入进度需要明确选择。预览按番剧列出新增与修改，分开报告各数据源的结果。确认使用该次预览的数据和库版本，过期或有并发写入时重新预览。网页和桌宠显示一致的同步结果。
3. **分钟级更新时间。** 将首播日和下一次预计更新分开显示，使用北京时间，示例为「预计周五 23:30 · 某平台」。优先使用手填排期，其次是所选平台和地区的已知时刻，再展示标明来源的原播周档。能按 Bangumi ID 匹配的时刻批量从缓存填充；只有日期时显示「时刻未公布」，同名匹配交给用户确认。已采用的排期供本季、本周、桌宠提醒和日历导出共用。
4. **修复排期写入与撤销。** 单部、批量和详情使用相同的排期校验。星期未知时先补星期，批量调整明确跳过暂停和归档记录。顺带完成撤销冲销观看统计，随后继续[补番起点和备份预览](PLAN-v0.27.md)。
