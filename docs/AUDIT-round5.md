## 1. [P1] 桌宠同步可覆盖同时记下的进度

位置：`tools/sync_bangumi.mjs:77`、`:132-134`；调用点 `pet/Pet.cs:3759`、`:3794`。

同步先读取整个库，再等待网络，最后把基于旧库合并的结果直接 `writeFileSync` 覆盖。桌宠手动/自动同步直接启动此脚本，绕开 `server.mjs` 的进程内写锁；因此面板同步入口的锁不能保护这两条路径。脚本也没有使用 `lib/library.mjs`，不会压入撤销栈或生成滚动备份，写入也不是原子的。

实测：模拟同步挂起网络响应 → 面板 `/api/progress` 成功返回 `ep_status:1` → 放行一份改变播出星期的同步响应 → 同步成功退出，磁盘进度变回 **0**。撤销深度同步前后均为 **1**，同步没有增加撤销点。

建议：桌宠统一调用服务端同步入口；同步完成网络获取后，在共享写入队列内重读最新库、合并、调用 `writeLibrary`。离线 CLI 如需独立写库，还需要跨进程锁或等效协调，单用原子 rename 不能解决旧快照覆盖新进度。

## 2. [P1] 便携包包含本机私人数据和配置

位置：`tools/pack_portable.mjs:34-35`、`:42`、`:64`。

`data` 被递归打包，排除规则只跳过部分扩展名/目录，并不会排除 `bgm.json`、历史、状态、撤销快照与每日备份。`.gitignore` 对自定义打包器不起作用。源码注释称库是“示例库”，实际上没有生成示例或清洗个人数据。

当前 `dist/TIARA-portable-0.26.0.zip` 已含：

- `data/bgm.json`
- `data/backups/2026-11-05/bgm.json`、`data/backups/2026-11-09/bgm.json`
- `data/history.jsonl`、`data/state.json`
- 多个 `data/undo/step-*.json`

当前包中的上述配置 **token 均为空**，本轮没有发现非空 token 已打包；但一旦配置 token，当前逻辑会原样带走，包括备份里的旧 token。个人追番库等数据也已在打包范围内。

建议：发行包只加入明确列出的默认配置、台词及单独维护的示例库。个人迁移备份应有独立命令。对 ZIP 条目加回归检查，直接禁止个人配置、备份和撤销目录出现。

## 3. [P1] 快速撤销会撤销上一笔，随后仍提交本次加一

位置：`panel/app.js:123-128`、`:764-766`、`:774-778`。

`bump()` 即时显示新数字与“撤销”，但延后 260ms 才提交。此时 `undo()` 直接请求服务端撤销栈，既不取消尚未发送的 `PEND/PTIMER`，也不等待正在提交的进度。因此撤销目标与用户刚看到的操作不对应；上一笔若是加番/移除等操作，还可能影响别的条目。

按当前前端时序调用真实接口复现：库中进度从 0 设为 3 → 点击加一（界面应显示 4，提交尚在等待）→ 立即撤销 → 260ms 后加一仍提交 → 最终磁盘是 **1**，不是撤销本次加一后期望的 **3**。这项是接口时序复现，未做浏览器点击实测。

建议：明确区分待提交、提交中、已确认三种操作状态；撤销待提交操作时取消/抵消对应队列并恢复界面；已提交操作须等待确认再撤销，或使用服务端操作 ID 对应撤销对象。

## 4. [P2] 接受 25:30，却没有把跨日节目带入次日清单

位置：`server.mjs:1198-1217`、`lib/today.mjs:158-163`；桌宠提醒依赖 `pet/Pet.cs:3607-3618` 的今日 `showN_unix`。

时刻接口允许并原样保存 `25:30`，但是 `buildToday` 只读取当前自然日的星期桶，没有合并前一天的跨日节目。`lib/time.mjs` 的 `splitClock` 没有接入这里。

实测：周一节目填 `25:30`，周一 23:59 仍在 upcoming；到周二 01:30，`today=[]`，提醒列表也为空。桌宠正常跨日重建后不再拥有这条今日节目，无法在其实际开播时提醒。ICS 自己会做日期进位，因此导出和今日清单还会出现不同口径。

建议：明确持久化格式。可以在输入时规范为次日 `01:30` 并同步星期，也可以保留广播日/扩展时刻，但所有排片与提醒必须按实际开播时间戳计算。增加周日→周一以及月末/年末跨日回归。

## 5. [P2] 按首播日期推算的已播集数在跨周后倒退

位置：`lib/today.mjs:109-121`、`:130-136`。

无手工 `ep_expected` 时，`floor((today-start)/7)` 已按首播日期计算完整周数，又叠加相对日历星期的 `weekDelta=-1`，会重复扣减。

实测：首播日为 2026-11-06（周五）、23:00 开播的节目，11-06 23:30 返回已播 **1** 集；到 11-09 周一中午却返回 **0**。这会让待看和落后数在周一无故减少。

建议：`start_date` 推算分支独立计算已发生的播出次数，只在当前这一期尚未到开播时刻时扣减。不要复用为手填“本周预计集数”设计的星期差修正。增加从首播前到次周每天的连续时间测试。

## 6. [P2] 切换时制或尺寸会删除生日等设置

位置：`server.mjs:93-115`；生日读取位于 `pet/Pet.cs:2101`。

`readSettings` 只返回 `clock/pet_scale`，`writeSettings` 又仅用这两个字段重建整个文件。其他功能合法使用的字段因此在保存普通偏好时消失。

实测：初始 `{clock:'30h',pet_scale:1,birthday:'11-05',custom:'keep'}`，POST `{clock:'24h'}` 后磁盘只剩 `{clock:'24h',pet_scale:1}`。

建议：保留原始配置对象，只验证并更新允许修改的字段；设置的读改写也应串行化，避免不同客户端同时保存互相覆盖。

## 7. [P2] 合法 JSON 标量让写请求一直没有响应

位置：`lib/http-util.mjs:47-51`、`server.mjs:445-468`、`:907-908`，其他 `if (!body) return` 路由同构。

解析器接受任意 JSON 值。合法的 `null/false/0/""` 返回成功后，被调用方误当作“解析器已经回过错误响应”的哨兵，直接返回，实际没有写响应也没有结束连接。

实测：这四种请求体发往 `/api/settings`，均在客户端 500ms 截止后报 `TimeoutError`；服务仍存活，随后健康检查 200。不是再次打死进程，而是请求悬挂。

建议：统一要求顶层为非空、非数组的对象，不符立即 400；解析成功与失败使用可区分的结果结构，不以合法 JSON 值作为错误哨兵。

## 8. [P2] 自动同步的 12 小时缓存检查找错文件

位置：`pet/Pet.cs:3788-3794`；`tools/sync_bangumi.mjs:57-62`。

桌宠查 `cache/bgm/calendar.json` 的修改时间，同步脚本实际生成 `calendar-YYYY-MM-DD.json`。专项同步后目录实测只有 `calendar-2026-11-09.json`。在没有旧版无日期文件的正常目录中，每次启动都会重新联网；有旧文件也不会被本脚本更新。

建议：使用明确的同步成功时间戳，或让读写双方共享一个缓存元信息文件。增加“成功同步后 12 小时内再次启动不发请求”的验证。

## 9. [P2] 自检仍可通过开机自动同步改写库

位置：`pet/Pet.cs:325`、`:392`、`:3780-3794`。

这是静态调用链确认，未运行真实桌宠自检：构造函数先设置 `_selfTest`，但仍无条件调用 `TryAutoSync()`；后者没有 `_selfTest` 保护，直接执行可写库的 `sync_bangumi.mjs`。手动 `SyncBangumi` 里的 dry-run 判断无法覆盖这条独立路径。若网络返回元数据变化，自检就会写库；第 8 项又使它更容易触发。

建议：自检模式在启动后台任务前禁止自动同步，或将整个自检根目录指向专用 fixture。用调用监测验证自检不运行任何写库子进程，而非只保护交互按钮。

## 值得更新的工程部分

1. **把数据契约真正贯穿各入口。** `lib/library.mjs` 已具备基础，但同步、CLI 恢复等工具还需逐个核对，确保共享备份、撤销、原子写和并发策略。文件拆分应在行为收敛后进行。
2. **补跨层回归。** 现有 `test/server.test.mjs` 把三个构建工具替换成 `process.exit(0)`，无法证明库修改会正确传入 today/ghost。保留快速接口测试，再加少量真实构建的临时目录集成测试，覆盖本报告的时间及并发场景。
3. **完善测试隔离。** 当前服务的 `snapshotDaily()` 动态导入固定位置的模块，模块内部 ROOT 由自身文件位置决定，没有接收服务的 `--root`；因此原接口测试虽隔离了库，启动时的每日快照仍可能操作项目真实备份目录。应显式传 root，并验证不会触及夹具外目录。本轮专项探针复制服务与模块到临时目录并替换快照模块，避免此问题。
4. **校准 CI 和文档。** CI 语法扫描仅收 `.mjs`，应包含新拆出的 `panel/app.js`；README 的“69 例”测试数量已与实际 124 不符。无需为修复这些问题引入前端框架。

建议执行顺序：先处理 1/2/3，接着 4/5，再补 6/7/8/9 和相应回归。真实浏览器的快速点击、多显示器/DPI 与 SSP 宿主行为保留为后续人工/环境验证项，不能由本轮编译和接口测试代替。
