## 大番库性能

用包含连载、补番、暂停和归档的 500 与 2,000 部合成番剧，在同一台机器通过内置 Node.js 启动。每个接口预热三次后取 11 次回环 HTTP 请求的中位数，计入读取完整响应时间。优化后重测同一份数据。

| 关键路径 | 500 条，优化前 → 后 | 2,000 条，优化前 → 后 |
| --- | ---: | ---: |
| 面板首页数据 | 30.5 → 8.8 ms | 401.3 → 23.7 ms |
| 七日只读看板 | 2.3 → 2.4 ms | 7.9 → 7.5 ms |
| 单部番剧详情 | 1.2 → 1.2 ms | 2.5 → 2.5 ms |

数值反映本机后端与传输，页面绘制和在线资料延迟另计。

## 双屏实机检查

混合缩放和副屏停用后的实机回归已在 [v0.58.1](VALIDATION-v0.58.1.md) 完成。下文保留 v0.58.0 的单屏验收记录。

在当前单屏（125% 缩放）上，用解压的便携包和独立测试状态核对了部分路径。状态保存的最后位置指向一台不可用的显示器时，真实 WPF 窗口启动后回到主屏已存的位置。隐藏后调用同一条托盘召回路径，立绘回到同一坐标。由桌宠保存状态后再次启动，主屏位置仍正确，状态文件中也保留了不可用屏幕原有的坐标。仍需在扩展桌面上使用两块不同缩放的显示器，完成下面的检查。

重新检查时，Windows 显示设备列表有两台显示器，当前拓扑为「仅外接屏」，且只有一条启用的显示路径。须先在 Windows 投影设置中选择「扩展」，再给两屏设置不同的缩放。

1. 解压便携包到测试目录，在两块屏幕各保存一个不同的桌宠位置。将鼠标放到另一块屏幕后从托盘召回，确认召回到该屏保存的位置。重启确认恢复到最后所在的屏幕。
2. 从面板打开只读看板，在副屏全屏后检查排片文本，再按 Esc 退出。桌宠继续留在原屏。
3. 桌宠在副屏时断开该屏，确认召回后整个立绘能在主屏显示。保持副屏断开重启再检查一次。
