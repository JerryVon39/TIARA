# TIARA v0.42.0 全项目待办评估

评估对象是本机 v0.42.0 源码、[现有待办](BACKLOG.md)、两种本地发行包，以及已有验收记录。下表覆盖原待办的 54 个未勾选条目。这是一份改稿建议，没有改动待办状态、程序或发行包。标为「远期」「试验」的条目可以留作备选，不占近期版本名额。

本轮重新运行了项目 CI，169 项测试全部通过，另有一条本地桌宠日表日期不是当天的提示。发行清单单独校验失败。SSP 快照和历史写入异常用合成数据复现，迁移问题用解析器验证。没有用真实账号同步，也没有在干净 Windows 上重新安装两个包；这些仍是发布验收。

## 应新增的修复和发布门槛

| 优先级 | 建议加入的事项 | 依据和验收 |
| --- | --- | --- |
| 发包前 | 公开 SSP 包与私人快照分开 | 用合成番库实际生成快照并打 SSP 包，测试番名进入了包内 `ghost/master/today.json`。本机已有的 v0.42.0 两个 ZIP 的这些排片数组为空，不能据此断言已有发布泄露。公开包从空库生成，私人快照另命名并明确范围。用合成番名、称呼和补番进度检查两个公开包都无残留。见 [SSP 打包](../tools/pack_ssp.mjs) 和 [便携打包](../tools/pack_portable.mjs)。 |
| 发包前 | 干净源码基线和当前版本产物校验 | 本地 Git 没有远端配置，且待办、面板脚本和若干核心模块还未纳入当前检出的 Git 记录；这不能判断远端的状态。`dist/manifest.json` 未收录两个 v0.42.0 包且校验失败。Git 忽略了 `data/history.jsonl`，但没有忽略程序生成的年度归档。将用户数据、默认模板与发布暂存目录分开，按版本验收两个 ZIP、版本和 SHA-256；缺少预期产物或出现额外产物都应失败。 |
| 高 | 观看进度与历史一起落盘或恢复 | 用临时番库让历史文件无法追加，记一话返回 HTTP 200 且进度由 2 变为 3，但没有历史可核算。普通记账和重看都走同一写入路径。验收失败时明确告知、仍可安全重试，重启后统计、撤销和进度一致，不重复记账。见 [写入历史](../server.mjs#L571) 和 [保存进度](../server.mjs#L782)。 |
| 高 | 合并三方身份与字段保留 | 原核查复现了手动条目、已入库目标和线上条目有首播日期冲突却仍能合并，以及手填 `25:30` 被另一条空时刻覆盖。保留绑定/批量整理的交付记录，在待办另列回归修复。日期冲突时停止合并，周档冲突时先让用户选，合并前后核对进度、历史、提醒和排期。见 [合并规划](../lib/library-organize.mjs#L49)。 |
| 高 | 更正首轮完结日期，并补齐重看误记恢复 | 原核查复现了指定撤销最后一话再用其他日期补记，完结日期仍沿用旧值。重看记录已有独立轮次，但观看历史不能指定撤销重看。先修首轮回归，之后把重看撤销并入逐集记账，保留手动完结的独立语义。见 [撤销写回](../server.mjs#L1246) 和 [历史操作](../panel/app.js#L2360)。 |
| 高 | 迁移校验覆盖新增数据结构 | `parseMigration` 接受含有 `rewatches: [null]` 的合成备份，详情代码直接读轮次对象的属性。恢复预览应拒绝损坏轮次，指出出错条目，并验证有效旧档正常通过。普通番库回滚与整份迁移的恢复范围也应清楚区分。见 [迁移解析](../lib/migration.mjs#L84) 和 [重看详情](../panel/app.js#L1917)。 |
| 后续可用性 | 区分暂时不看、弃番和移除误加 | 排片上的「移出在追」直接从在追列表移除记录，和暂停/弃番的保留语义不同，且待看误加没有对等入口。对误加条目提供带预览、可找回的处理；有观看历史的条目明确显示影响。让重复条目后续仍能处理，不在删除中暗中丢历史。见 [移出在追](../server.mjs#L831)。 |

## 建议替换旧排期

1. **v0.42.1：数据与发行修复。** 先隔离公开 SSP 包和私人快照，保护历史落盘与迁移，修复合并和首轮完结日期，再建立两个包的发行门槛。
2. **v0.43.0：可控同步和可恢复操作。** 同步差异、状态映射和手填字段保护作为同一个流程；优先检查预览确认、局部失败、刷新冲突。桌宠「找回桌宠」与开机路径诊断可独立交付。
3. **v0.44.0：逐集记账。** 合做每话、跳集、回补和可撤销的重看，再考虑回写 Bangumi 和统计回顾。同时用大库或旧档验证新数据口径。
4. **再排提醒与陪伴两条线。** 提醒先完善稍后提醒的生命周期，才增加提前量和日历订阅；陪伴先解决气泡打断与台词收藏，再做里程碑和新内容。

原待办中仍指向 v0.31–0.34 的「后续排期建议」和只剩一行的评分表可以从活跃区移除。已交付内容保留历史，仅对已复现的边界问题新建修复项。建议活跃区按「待修缺陷」「下一版」「候选 / 试验」分层；文档、性能与键盘检查作为相应版本的验收条件。
