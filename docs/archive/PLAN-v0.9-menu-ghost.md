## 1. 右键菜单为什么「不像伪春菜」

现在 `pet/Pet.cs:528 BuildMenu()` 一共 11 项，全平铺：

```
番组表 / 打开网页番组表 / 说句话 / 重算今日数据 / 同步 Bangumi
────────
窗口层级 ▸(置顶/普通/沉底)   桌宠尺寸 ▸(5 档)
────────
省电模式 / 开机自启 / 隐藏到托盘
────────
退出
```

五个具体毛病（不是「审美问题」，是可用性问题）：

1. **最常用的动作不在菜单里**——「记一话」只在气泡行和托盘有，右键找不到。用户翻菜单时是在「想干点什么」，这时候给的是「重算今日数据」。
2. **状态为零**——菜单不告诉你今天有几部、还差几话、下一集几点。任何窗口的右键菜单都该反映「现在的状态」。
3. **开发项与用户项同级**——「重算今日数据」「同步 Bangumi」和「说句话」并列，前者是排障动作，应该收进「高级」。
4. **没有「她」**——菜单全是系统词（层级/尺寸/自启），换成任何桌宠都成立。伪春菜菜单的魅力是「用角色的口吻交代同一件事」。
5. **交互粗糙**——WPF 默认 `ContextMenu`：无图标、无快捷键提示、无说明、宽度随最长项跳变、点空白处不关（`StaysOpen` 默认 false 但无 `Placement` 微调）。

对照橘花2：它的菜单是「人格脚本」发出的（`OnMenuOpen` + `\![open,menu,...]`），每一项都带台词、带条件显示。这才是「伪春菜感」的来源。

## 2. 新菜单结构（目标形态）

```
┌ TIARA · 副会長室 ─────────────────────────┐   ← 头部：禁用项，显示「今天 0 件 / 未処理 1 件」
│ 案件 ▸        今天 0 件 · 未処理 1 件      │   有番时逐条列出：23:00 药屋少女…  ＋記録
│ 番组表 ▸      气泡 / 网页版 / 重新排期      │
│ 說句話                                     │   ← 随机台词，带心情
│ 摸摸頭                                     │   ← 直连 NadeSay，带递减反应
├────────────────────────────────────────────┤
│ 業務 ▸        同步 Bangumi / 進階 ▸(重算数据 / 打開資料夾 / 日誌)
│ 顯示 ▸        層級 ▸ / 尺寸 ▸ / 主題 ▸(跟隨系統 / 暗 / 亮)
├────────────────────────────────────────────┤
│ 隱藏到托盤                                  │
│ 退出                                       │
└────────────────────────────────────────────┘
```

关键点：

- **头部状态行**：`今天 N 件 · 未処理 M 件`，M>0 时变红；没有番就写「今日は静かです」。
- **案件子菜单是动态的**：每部在追的番一行，格式 `23:00 药屋少女的呢喃 ＋`，点「＋」直接 `BumpShow`；空时给一行禁用的「今天没有要追的番」。
- **口吻统一**：菜单文字走 `talks.json` 的 `menu` 池（可改、可翻译），不在 C# 里写死。
- **快捷键**：`F1 番组表`、`F2 说句话`、`空格 记一话`（选中案件时）。
- **图标**：用 `Segoe MDL2 Assets` 的字形（系统自带，无需资源文件）。
- **`StaysOpen=false` + `Placement=Mouse`**：点外面就关，位置跟鼠标。

## 3. 天愛星人格设计（依据可查）

角色事实（[アニ図鑑](https://anizukan.com/characters/217327/tiara-basori)、[Anibase](https://anibase.net/ja/character/mO9G5/)）：
**馬剃天愛星（ばそり てぃあら）／Tiara Basori，16 岁，学生会副会长**，声优诸星すみれ。原作《敗北女角太多了！》。
- 外表**严格、认真**（厳格で真面目）；
- 实际**容易激动、容易误会（早とちり）、容易被带跑**；
- 从月ノ木言都那里没收了同人志后读了，**对 BL 产生强烈兴趣**，靠飞散的妄想自我刺激，**经常流鼻血**。

这套反差就是人格的发动机：**「副会长的威严」× 「一妄想就崩」**。我们的项目名 TIARA 本来就是她。

### 3.1 口吻规则

| 场景 | 规则 | 例 |
| --- | --- | --- |
| 日常 | 敬体、公事公办，像在写会议记录 | 「今日の案件は 0 件です。……静かですね」 |
| 催你 | 说教 + 轻微责备，但不刻薄 | 「会長。未処理が 3 件あります。目を逸らさないでください」 |
| 妄想 | 突然语速变快、句子变长、开始给两个角色编关系 | 「この二人、同じ傘に入る……つまり、そういうことでは？」 |
| 慌张 | 发现自己说多了，立刻切回公事公办 | 「……っ。い、今のは業務外の話です。忘れてください」 |
| 鼻血 | 极短的一句，配上 `surprise` 表情 | 「……鼻血が」 |
| 深夜 | 关心但嘴硬 | 「こんな時間まで……明日、起きられますか」 |
| 被摸头 | 先是「不届き者」，第 3 次开始不抵抗，第 5 次以后小声 | 见 `nade` 池 |

称呼：把你叫 **「会長」**（她是副会长，你是她管着的会长——这个错位本身就是笑点）；生气时叫 **「不届き者」**；偶尔漏出「あなた」。

### 3.2 番组 → 学生会 的隐喻（贯穿全局）

| 现实概念 | 她的说法 |
| --- | --- |
| 在追的番 | 担当案件 / 審査対象 |
| 记一话 | 一件処理完了 |
| 落后 N 话 | 未処理 N 件（滞納） |
| 本季表 | 新規案件リスト |
| 同步 Bangumi | 資料の更新 |
| 待看队列 | 持ち越し案件 |

这不是换皮文案，而是让每个数字都有「她在替你处理公务」的叙事——这才是伪春菜感。

### 3.3 新增人格变量（写进 `state.json` 的 `vars`）

| 变量 | 含义 | 变化 |
| --- | --- | --- |
| `affinity` | 好感（已有） | 摸头/记一话 +1，上限 100 |
| `imagination` | 妄想度 | 看番 +1，深夜 +2，上限 100；>60 触发妄想台词 |
| `fluster` | 慌张度 | 被点脸/被抓到妄想 +1，随时间衰减 |
| `nosebleed` | 鼻血次数 | 妄想度跨阈值时 +1，纯计数 |
| `caught` | 同人志是否已被你发现 | 摸头第 7 次起触发一次告白式台词 |

### 3.4 事件扩展（`Dispatch` 里加分支）

`OnMenuOpen`（右键打开时，她先说一句）、`OnMenuPick(动作名)`、`OnBump`（记一话成功）、`OnBumpRapid`（30 秒内连续记 3 次）、`OnCatchupFull`（未处理 ≥5）、`OnSyncDone` / `OnSyncFail`、`OnIdleLong`（15 分钟无操作）、`OnOpenPanel`、`OnDayRollover`。

每条事件都能在 `talks.json` 里挂池子，做到「人格是数据，不是代码」。

## 5. 明确不做

- **不换立绘**：用户已说明优先功能，且现有 5 张 surface 与 `faces.json` 的分层已经能跑。
- **不做多角色**：一个 ghost 一个人格，避免「对话对象漂移」。
- **不引入 LLM 在线生成**：离线是这项目的底线，台词全部落文件（`talks.json` 就是「人格数据包」）。
- **不动 `state.json` 的既有键**：只新增 `vars` 里的键，保证回退安全（日快照 + `data/undo` 已能兜底）。
