# TIARA v0.27.0 更新方案

先按[追番助手专项方案](TRACKING-ASSISTANT-REVIEW.md)修复账号、同步和分钟级排期。下列进度与恢复功能接着实施。

这一轮集中处理进度记录、补番起点和备份恢复。暂停、继续和归档沿用现有入口与数据。

## 1. 撤销同步更新观看统计

网页和桌宠共用现有「撤销」入口。一笔进度操作撤销后，番剧进度、观看历史、本周话数、累计话数和连续天数一起更新。

- 给新发生的进度操作分配标识，让撤销准确关联原来的记录。连点合并的一笔按实际增加的话数冲销，跨日撤销仍从原观看日期扣除。
- 继续用当前的版本校验和写入锁，避免旧页面撤销另一处刚写入的操作。失败重试也只能冲销一次。
- 现有历史记录照常读取。详情手填进度、撤销暂停或归档仍只改变相应的番剧资料和状态。

验收用例：今天只记了一话，撤销后进度、今日和本周统计均回到操作前，连续天数重新计算。连点合并记三话，撤销后整笔冲销。网页撤销后桌宠刷新看到同一进度。

## 2. 加入时选择补番起点

「本季」的单部加入和手动添加使用同一套起点规则。批量加入保留快捷入口，用同一个选择应用到这批番，并在确认前显示例外。

| 选择 | 已播至第 8 话时的结果 |
| --- | --- |
| 从头补 | 待看 8 话 |
| 已看到第 3 话 | 待看 5 话，初始化为第 3 话 |
| 从最新一话开始 | 待看第 8 话，记一话后进度到第 8 话，观看统计只增加 1 话 |

待看计算区分已播话数、观看进度和所选起点。完结番可用已知总集数，连载番根据本地排期推算时标注「按排期估算」。资料不足时仍可离线填写当前进度，页面把待看数量显示为未知。旧库继续按已有规则计算，暂停后恢复时保留所选起点。

验收用例：同一部已播 8 话的番分别得到 8、5、1 话待看。刷新后结果一致；从最新一话开始时，跳过的 7 话不会进入观看统计。

## 3. 选备份并预览恢复

把底栏「恢复上一版」扩展为「备份与恢复」。选择一个日期或版本后，预览会新增、移除或改动的番剧，优先显示进度、排期和在追、暂停、归档状态的变化。

恢复时先保留一份当前番库。确认操作以预览时的库版本为准；若期间又记了进度，先重新预览。恢复范围在确认前标明为整份番库，观看流水和偏好设置各自保留。单部番剧找回安排在后续批次。

验收用例：任选一份旧备份，预览能看到「第 8 话 → 第 3 话」和状态变化。确认后网页与桌宠读取恢复后的数据，恢复前的库仍能在备份中找到。

## 发布与后续

按上述顺序实现，每项通过接口测试和浏览器实测后，再用旧库副本跑完整回归。新版便携包验证没有系统 Node.js 时可启动、记账和恢复。GitHub 提交包含项目作者用 AI 制作并同意随项目发布的立绘，发布前同步更新旧的素材来源说明。真实番库、账号配置、观看流水与备份留在本地。

下一批优先做「跳过本周」「调整下一次开播」和「停止排片」。排期例外落地后，再统一接入单番静音、免打扰和稍后提醒。
